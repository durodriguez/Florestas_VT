        Diversity

        A common guideline for resilient urban trees: no more than 10% of them one species, 20% one genus, 30% one family, so that one pest or disease cannot take out a large share at once. The red line marks each limit.

        Pest and disease exposure

        Plants of the genera that some well-known pests and diseases of the northeast attack. This is exposure, not damage: it says where a pest would find hosts, not which trees are affected.

          How it would work

          1. A surveyor sends a file. They export from the survey app as now, and instead of emailing it, add it here with Add a survey file. The file is saved to survey/inbox/ in the project's GitHub repository.
          2. It appears here in a few minutes, once the site rebuilds, run through the importer as a dry run: new trees, visits, corrections, renumberings, the notes for review, and anything that blocks it. Nothing on the map changes yet.
          3. The approver checks it. Approve runs the importer for real, on GitHub: it writes the trees and visits, checks every row as now, moves the file to survey/imported/, and the site redeploys with the changes. Send back removes the file with a note saying what to fix.
          4. Every step is a commit in the repository's history, so any approval can be looked at again or undone.

          Who can do what. Anyone with the link can see the inbox, as everything in it becomes public on the map anyway. Adding a file and approving need write access to the repository: for the test run, only you, signed in once in this browser with a GitHub token.

          What is left to switch it on: the Add a survey file button, the two GitHub Actions behind Approve and Send back, and your token. Until then, survey files come to the importer as they do now.
